        ## Quickstart

        ```bash
        ./quickstart.sh
        ```

        This script setups everything for you.

        ## Installation

        ```bash
        npm install
        ```

        ## Local Development

        ```bash
        npm run start
        ```

        This command starts a local development server and opens up a browser window. Most changes are reflected live without having to restart the server.

        ## Build

        ```bash
        npm run build
        ```

        This command generates static content into the `build` directory and can be served using any static contents hosting service.

        ## Deployment

        ### Github Pages

        You can find an automatic build of the newest state at https://emexlab.github.io/

        ### SSH

        ```bash
        ./deploy.sh user@host
        ```

        This will build the site and upload it via ssh to the specified host as the specified user.

        :::note

        It's recommended to set up SSH keys beforehand. Otherwise, pass `-n` and expect several SSH password prompts during deployment.

        :::
    </TabItem>

## Writing Documentation

You should always use `.mdx` instead of `.md`.  
All folders directly in a `docs` folder must contain an `index.mdx`. These and all `.mdx` files directly in a `docs` folder should also contain a value for `sidebar_position` in the metadata.

```mdx title="exampleDoc.mdx"
---
sidebar_position: 2
---

# Example Documentation

...
```

:::note

Please follow the best pratices from [markdownguide.org/basic-syntax](https://www.markdownguide.org/basic-syntax/)

:::

:::tip

You can find more documentation at [docusaurus.io](https://docusaurus.io/docs/category/guides).  
The websites github is also a good reference point: [docusaurus/website](https://github.com/facebook/docusaurus/tree/main/website)

:::

## React
You can also contribute to the website in various other ways:
- Improving [components](https://github.com/emexlab/emexlab.github.io/tree/main/src/components/)
- Creating new components (your component must be used in atleast on page)
- Helping on [pages](https://github.com/emexlab/emexlab.github.io/emexDE/tree/main/src/pages/), for example this page

But please restraint from using swizzling to change the website (except if it's the offical way). Always look if what you're trying to do can be achieved using classes and CSS.

:::note

When writing react code please follow the best pratices from [react.dev](https://react.dev)

:::

:::warning

Changes to `/static/bootstrap` and any `credits.mdx` will always be rejected!

:::
